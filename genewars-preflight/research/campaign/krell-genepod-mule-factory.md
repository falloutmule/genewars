## Bounded pure-plan contract

1. Check signed live count at `11C2B0` against 300 before consuming RNG. Find the first record with type byte `+6 == 0`. Preserve that complete prior record, including pointer normalization policy.
2. Choose initial physical height from parent `+27` when parent exists, otherwise terrain sampler `7B140(position)`. Ground `+11` is independently sampled at the new position by initializer `1EC60`; a parent's physical height must not replace ground.
3. Consume exactly three source RNG draws in order: speed `64*(r1%20)`, pitch `r2%256`, yaw `8*(r3%256)`. Each `r` is the high byte of the source's next 16-bit seed; preserve ring/log/count ordering. These are factory launch values, later overwritten by the successful Genepod caller's additional three ejection draws.
4. Set species `+7A=4`. Invoke the behavior of virtual `+78 → 1EC60` using type 1, owner, slot, XY, physical height and angles. This clears only linked-reference kind bytes `+2/+5`, retaining their ID words until world linking. It writes type, ID, owner, XY, sampled ground/shade; target words `+B/+D=0`; animation `+19/+1A/+1B/+1D=0`, `+1C=1`; flags word `+15=0`; angles `+39/+3B/+3D`; trig-derived velocity `+2D/+2F/+31`; acceleration words `+33/+35/+37=0`; radius `+2B=16`; physical height `+27`; byte `+53=1`, `+54=0`, and `+4A &= 3B`. Other bytes remain unchanged.
5. Factory overrides flags word `+15=280`, word `+60=0`, heading `+4B=yaw`, animation selector `+19 = ((((yaw >> 7)+1)>>1)+1)&7`, radius `+2B=80`, quality byte `+76=q`. Virtual `+7C → 1F060` supplies that heading-based animation selector.
6. Let `pct(m) = m + min(q,100)*(100-m)/100` using source integer truncation, and `L = 19000*pct(30)/100`. Energy `+66=L` for a parent, and `L-(L>>4)` for a null parent. Set stage `+79=0`. Let reserve `R=L>>3`. On the admitted cases energy exceeds `L-R`, and hunger byte `+77=max(16,(L-energy)*255/R)`. Then max-health word `+62=((160*pct(40)/100)*(hunger+1)>>8)+32` and max-secondary word `+64=((80*pct(30)/100)*(hunger+1)>>8)+16`. The alternate hunger-255 branch uses retained max fields and requires its own admission if later needed.
7. Set state `+5E=8`, substage `+5F=0`, timer word `+6C=0`, current secondary `+6A=+64`, current health `+68=+62`, inherited byte `+78=parent[78]` or zero, and `+7B=255`. Virtual `+84 → 1EE50` clears word `+3F`, applies word `+49 &= EFE8`, clears `+54` and applies byte `+16 &= 3F`. Virtual `+60 → 5A1C0` chooses the actual Mule animation resource, without another RNG draw.
8. Return the prepared record to an atomic world adapter. Source `8AC60` links it into the actual terrain-cell head, updating any prior head backlink. Increment global creature count and, only for owner other than neutral 4, owner dword `+6F9`. Do not claim success if pool/link validation fails.

For null-parent quality 35: energy 9619, hunger 127, max/current health 80, max/current secondary 37. For actual parent quality 50: energy 12350, hunger 16, max/current health 39, max/current secondary 19. Both begin state 8/substage 0, timer 0, inherited byte 0 in these fixtures, and `+7B=255`.

## Reuse and integration boundaries

Use existing `actor_activation::TrigTables` and its established signed table arithmetic for velocity. `creature_world::MuleAnimations` and `CreatureAnimationBinding::MuleSelector4` already represent the resource binding. The existing skill and lifecycle formulas in `creature_world.rs` are useful comparison material, but **do not call `refresh_mule_lifecycle` unchanged**: it decrements energy, unlike this initialization path. Existing common physics and Mule callback components can be reused after admitting the actual newborn state and owner.

`CreaturePool::from_packed` is mission restoration, not a factory. `replace_record_checked` explicitly forbids identity changes and cannot activate an inactive slot. A new atomic factory commit must validate the prior free slot and attach its typed animation binding while preserving opaque/pointer bytes according to the existing policy. Root owns this shared adapter; this packet adds no Rust changes.

The successful Genepod caller further overwrites launch angles/velocity with its own three draws, raises physical height by `0xF00`, and stores the newborn slot in building word `+3A`; see `krell-genepod-production.md`. The source-prepared natural birth instead resumes its own caller. Do not mix these two post-factory paths. Remaining proof is native pure-plan equality, complete world/link transaction equality, then the actual caller and subsequent newborn callbacks. An owned newborn must pass ordinary selection/movement before it can satisfy the next player-visible task of moving a Mule toward Krell's marked zone.
