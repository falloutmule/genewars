# Krell: Genepod positive work and production contract

Reference is the pinned QA BETA V5 CD executable, SHA-256 `4bdf296febc88984aab6939fe3f3ef3196891f0be9bcb84a9283ab3b668a60ba`. This is source recovery and bounded literal testing, not native production or mission acceptance. Research qualification and ordinary action-8 input are covered by `krell-mule-research-command.md` and `../variants/genepod-human-producer.md`.

## Ordinary paid work

Start opcode 12/handler `814A0` sets Mule work `building+36 = 75 >> grade`, initial-work word `+34`, and species `+33 = 4`. It charges the division remainder immediately. Human requests remember the payer in `+3A`; see the separately proved command contract.

Completed-building callback `451F0` reaches selector 0 at `45470`. The outer callback requires completion flag 1 and excludes flag `40`; the selector's own eligibility additionally excludes flag `100`. A selector-ineligible branch clears work at `45D84`, but an outer skip does **not** imply that write. Preserve this distinction when integrating the branch into the full callback.

With positive work, `454C7` sets extra power consumption byte `+3F = 3`. A live powered flag 4 allows a work step every callback. Without that flag, `454DD..454ED` admits a step only when the original frame counter is divisible by 6. **Power is a speed prerequisite, not an absolute production prerequisite.** The shared prefix first reduces signed power timer `+3D` by mapped selector consumption plus the previous `+3F`; if expired it clamps to zero and clears powered flag 4 (unless the separate flag-100 branch applies). The common tail caps the timer to 200 and decrements nonzero `+3F`.

Each admitted work step checks signed wrapped owner funds `+4A3 + +4A7 >= 1 << grade`. Insufficient funds pauses work without a debit. Source then selects the actual payer: AI-owned buildings use owner, human-owned buildings use remembered byte `+3A`. The payer's primary funds are consumed first, then secondary, using wrapping 32-bit arithmetic. The owner's affordability check and payer debit are distinct reads; do not silently collapse them outside the ordinary same-owner case. An AI funds-identity player retains the source secondary-funds floor of 1000. After payment, work decrements exactly once (`455B0..455B7`). Grade-0 Mule therefore costs 75 total work payments; its full duration also depends on power/frame phase and any funds pauses.

## Completion decision and newborn

On reaching work zero, source sets animation frame `+1B = 1` and computes signed quality `payer.research[species] >> 11`. Grades below 2 cap this at 100. A gameplay RNG draw, with original ring/count logging, produces `(next_seed >> 8) % 100`. `45687` takes the factory path when this value is **less than or equal to twice quality**; larger values take the failed-production path. Do not substitute a uniform probability model for the source's bounded RNG values.

Current carried Mule research `0x11800` gives quality 35, so the first attempt admits rolls 0..70 and fails on 71..99. A failed attempt is an original production result, **not a mission loss**, and must not be avoided by reseeding.

Factory path (`4568F..459E3`): request sound `1A`, then call `5A210` with owner = selected payer, species = building species, position = building XY, quality's low byte, and null parent. Capacity is checked by factory `5A226..5A232` against 300 live creatures; null return is a distinct allocation/capacity result. For a successful allocation, the building generates three further ejection parameters: speed `0xF00 + 64*(draw%100)`, pitch `2*(draw%50)`, yaw `8*(draw%256)`. Source trig tables generate the velocity, and physical height is raised by `0xF00`. Building word `+3A` then becomes the newborn creature slot, replacing the earlier payer-byte meaning. Do not retain the payer interpretation after completion.

Factory `5A210` itself initializes shared creature state, statistics, animation and vtable callbacks, sets state `+5E = 8`, stage `+5F = 0`, clears `+6C`, inserts the live creature in the terrain cell through `8AC60`, increments live count, and increments owner's `+6F9` for a non-neutral owner. The parent is null on this path. Successful allocation is not proof that its state-8 ejection and subsequent ordinary owned-Mule commands are already implemented.

On successful allocation, research increases by `(grade+1)<<11`, capped at `(50 + 25*player[6E1])<<11`; a subsequent shared factory-path increment adds `grade<<6` under the same cap. Null factory return writes sentinel 301 to building word `+3A` and bypasses the first increment, but still reaches the second. At grade 0 a null return therefore adds no research. These are separate outcomes; do not report a nonexistent newborn as successful production.

Failed quality roll (`459E8..45D82`): sentinel 301, sound 8 plus a randomized sound 1C..1E, a burst of 3..8 selector-20 effects with original RNG-derived launch parameters, and research increase `0x800`, under the same cap. Payment is not refunded. Work remains zero. The common tail advances the original BGENE animation and emits the existing presentation queue request. The player can make another ordinary production request when the producer's animation/work/input gates admit it; no automatic repeat job is written here.

## Reproducible evidence and next implementation slice

`python -B scripts/ghidra/genepod_positive_work_contract.py` passes **108 literal work/payment branch cases**, one distinct-owner/payer case, and **80 literal quality/RNG decision cases**. Pins and results are in the adjacent JSON. The probe stops explicitly at `45D8E`/`455C2` for work and at `4568F`/`459E8` for the decision. It neither stubs a successful factory nor claims full-callback equality. Its flag tests describe the entered selector branch, not bypassed outer paths. No Rust/Cargo or original execution is used.

The next implementable player-visible slice is an ordinary Mule job that visibly consumes funds and progresses at the source cadence, with typed completion requests. Completing that slice still requires full-callback composition against the live power prefix/common animation tail. The next terminal slice must implement **both** quality outcomes with exact RNG, atomic creature/effect pool allocation, factory statistics/map links and state-8 ejection. Existing `5A210` exports contain the source; the remaining uncertainty is unproved integration of its transitive callbacks and resulting owned-Mule runtime, not a missing research action or a need for another campaign survey. The actual subsequent player action is selecting the resulting owned Mule and issuing its ordinary move toward Krell's marked zone, once that command and ejection admission are verified.
