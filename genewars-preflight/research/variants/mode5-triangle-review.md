# Independent mode-five triangle review

The repaired native implementation passed 5,880 cases: 77,193 prepared rows, 2,181 complete framebuffer comparisons and 3,145,393 written pixels. The review uses the source's conditional dispatch tree, repeated wrapped additions through omitted rows, and the separately reviewed 72-bit span accumulator. It does not import the source validator's preparation model. Inputs cover all cyclic permutations and reversed winding, clipping above/at/below the middle, full signed32 attribute patterns, coordinate admissions, unsupported general zero width and public prepared-row mutations. Counts and input/code hashes are in [the receipt](mode5-triangle-review.json).

One defect was reproduced and repaired by the implementation owner. A valid flat-top triangle `(1000,0),(1010,0),(1005,3)` with height 3, width/pitch 640 and a 1,920-byte frame was entirely right-clipped. Its final empty span retained start x 1003, and forming a zero-length destination slice at offset 2283 panicked. The caller frame remained unchanged. `draw_mode5_triangle` now skips empty spans before forming a destination slice. The original independent [reproducer](triangle-empty-repro.rs) remains available; the full review includes this geometry and an extreme public empty-span mutation.

Whole-frame comparisons include pitch padding and external sentinels. Late invalid shade/source and invalid public y values must leave every caller byte unchanged; invalid width, pitch, height and frame size are checked separately. Existing focused native tests also cover framebuffer extent multiplication overflow. No additional defect was found after the empty-span repair.

The safe port's coordinate/clip admissions and zero-general-width rejection restrict source behavior intentionally. These checks establish explicit-input row preparation and sampling, without choosing a scene, initial camera, live lighting, resource order or visibility policy. Original machine code and GUI execution were not used.
