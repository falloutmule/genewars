# Input-free empty gate probe 002

Prepared and statically/model checked; root alone launches, observes and releases this probe. No game executable, original asset, disc image or original mounted directory is present. Its C drive contains only independently generated YIELD.COM, YIELDGAT.BAT and fresh nonce markers; Z is internal. It reuses the exact run003 config and verified portable SDL2 executable. Default `prepare` and `launch` start no process.

```text
python -B scripts/reference/input_free_probe.py launch --open-probe
python -B scripts/reference/input_free_probe.py inspect
python -B scripts/reference/input_free_probe.py release
python -B scripts/reference/input_free_probe.py finish
```

Run from the preflight directory. Keep the first command's live parent session. Both host and emulator impose 180 seconds. stdout/stderr, process identity, actual exit and end time are private. Inspect requires the live exact PID/image/start time, exactly C/Z, secure-mode entry, refused E mount, mouse_emulation always and fresh waiting nonce. Root must first activate and capture the actual target window. Release exclusively creates a marker permitting only an ECHO sentinel and EXIT. `abort` creates the separate stop marker for an unreleased probe. `finish --observations <private-probe-json>` binds optional operator observations; it never infers successful activation from a sentinel alone. Preserve this used probe rather than relaunching it.

The independent helper is 27 bytes, SHA256 `2e5c8a0491dc099d1296389394e1a659f92eff2b91cf8c310b3c56f35a56aa09`. Independently authored assembly and byte generator are in input_free_yield.py; assembly and executable stay private. It saves DS, reads the low16 BIOS tick at 0040:006C, then exits when that word changes or after 65535 comparison polls, restores DS and uses DOS normal process termination. It performs no keyboard reads, synthetic input, file/network/port operations, interrupt-flag changes or sleep syscall. Reading a changing word handles low16 wrap. A fixed comparison bound also exits when IRQ ticks are paused. This is bounded guest polling, not a calibrated real-time delay or guaranteed SDL event yield.

The official release [BIOS header](https://github.com/joncampbell123/dosbox-x/blob/dosbox-x-v2026.10.01/include/bios.h) defines the tick address as 0x46C; the [BIOS timer handler](https://github.com/joncampbell123/dosbox-x/blob/dosbox-x-v2026.10.01/src/ints/bios.cpp) updates that value. The [DOS loader](https://github.com/joncampbell123/dosbox-x/blob/dosbox-x-v2026.10.01/src/dos/dos_execute.cpp) starts COM code at PSP:0100, establishes its stack and enables interrupts in its execution path. The [machine loop](https://github.com/joncampbell123/dosbox-x/blob/dosbox-x-v2026.10.01/src/dosbox.cpp) dispatches guest CPU work and pumps graphics events. Entering guest execution should give this machine loop an opportunity that a tight host shell IF/GOTO loop may lack; actual activation remains the experiment. Release-tag sources were privately downloaded and hashed, not copied into reconstruction code. Source review does not establish that the distributed executable is a reproducible build of those sources.

SOL-01 independently checked branch destinations 0115 and 010D, stack balance, no input and the poll bound. An independent Capstone disassembly covers every byte; its BSD3 license was checked before private wheel extraction. A small instruction interpreter checks no tick change, wrap, change on the last poll and all 65536 successor tick values. These are model/static checks, not a DOS/IRQ/SDL execution result. The readiness receipt records source/tool/script/config hashes and default-no-process/mutation/mount/nonce/watchdog guard checks. The validator is a prelaunch check because it temporarily mutates/restores the helper to test rejection.

Probe001 used CHOICE and timed out without release or sentinel; its receipt is retained. This helper removes CHOICE's synthetic Y/keyup race. Actual operator keyboard events may still be queued by DOSBox; this probe does not promise to drain user input. It does not prove the root cause of prior activation failures. Do not transplant it into an original gate until the empty probe has passed visible supervision, release and actual process completion. Original security limits remain: private mounts and secure mode reduce access, but DOSBox is not an OS sandbox and host watchdog/identity checks remain required.
