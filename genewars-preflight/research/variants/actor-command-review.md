# Independent opcode3 actor command review

**Passed:** 323,532 native setter cases and754,688 resolver cases matched an independent reference model. The setter comparison checks69,599,999 bytes across whole records and surrounding guards, not only the expected fields. The adjacent JSON pins the module, seven instruction exports, opcode table, independent Python/Rust harness and native output. No original, emulator or GUI ran.

For an admitted signed global actor ID0..19 and exactly200-byte record, flags+0x71 mask0x10 returns unchanged before reinitialization checks. Otherwise the bounded setter rejects old flags+0x57 mask1 or nonzero byte+0x82 atomically. Successful final writes are flags+0x57 OR2, byte+0x5B zero, and the resolved signed16 coordinate pair at both+0x5C and+0x0B. Requested coordinates are correctly returned in the receipt while the final target contains the resolved pair. Every other byte and guard is preserved. Safe ID/length validation and atomic rejection deliberately precede the original's potentially unsafe or partial writes.

The resolver oracle uses the original low-word doubling, subtraction, arithmetic right shift and sign extension, independently of the production modulo formula. Tests cover every signed16 current word against near/far/seam deltas, distance4096/4097, all terrain classes and avoidance masks, obstacle flags, blocker9/10, extreme nonnegative weights and invalid input rejection. Near points return current; farther accepted points return requested; other farther points require backward search. Invalid terrain/negative weight are rejected even for near points as deliberate safe input admission. Environmental virtual-call effects and the backward search are outside this helper.

No production mismatch was found. `PrecomputedResolvedTarget` is explicitly a caller value, not a validated occupancy result or trusted provenance token. The caller must bind the supplied record to the global actor ID and establish owner/type/ready/state, projected point and controller gates. Newly placed actors are not made command-ready here. The setter changes pending actor command state; it does not perform travel, animation, work, harvest/cut, landing activation or a complete mission dispatch. Those boundaries remain explicit before gameplay integration.
