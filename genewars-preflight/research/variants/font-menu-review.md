# Independent font and static menu review

Passed against the current assets/render source and root's headless menu BMP. `font-menu-review.py` builds private native libraries directly from those source files and runs an independent harness; it opens no GUI and executes no original. The JSON receipt pins source/harness/input/output hashes and thirteen private static listings.

All seven supplied CD font pairs (FONT0–FONT5 and FONT7) were checked against exact manifest source hashes and bounded RNC output receipts. All 1,190 glyph records matched an independent instruction-derived oracle: 142,315 indices and the same number of explicit opacity bytes, containing 65,162 opaque pixels. The oracle follows the raw zero-flags A7730 branch: positive controls consume the complete literal run but copy at most remaining width, negative controls leave transparent pixels, and row scanning realigns subsequent rows. Literal palette index zero remains opaque. Synthetic overlong runs followed by extra controls and a second row verify alignment and clipping beyond the real samples. Record lookup rejects usize::MAX before indexing and uses checked multiplication/addition.

The safe decoder requires a terminator for every declared row, including the last. Original code can return once the final visible row is complete, before its terminator. Native consumed counts therefore describe bounded complete-stream validation, not an exact reconstruction of the original final source pointer. This deliberate stricter rule is documented in the API notes; it does not change the validated real glyph pixels. Zero dimensions return empty output without dereferencing an irrelevant offset.

The exact English TEXT input produces 604 byte strings, consumes 36,609 bytes and retains one trailing NUL. All single-line strings admitted by each font matched independent width-minus-one measurements. The renderer deliberately rejects controls, absent glyphs and zero-width glyphs; it does not claim the original control formatting, kerning or newline behavior. Native line surfaces matched independent compositing with negative x, right-edge and bottom-edge clipping. Space advances without painting.

The entire existing 640×480 headless menu BMP matched an independent composition, all 307,200 pixels and 921,600 RGB channels. This separately parses IFTITLE's raw sections and uses animation0 normal frame0, components1/2/3 at the traced local positions, three controls at x140 and y115/186/257, and text indices255/258/259 centered at312. Widths246/151/85 produce left positions189/237/270. Descriptor pointers independently bind FONT2 and TITLESCR.PAL; the comparison uses the explicit presentation conversion floor(RGB6×255/63).

This establishes the bounded normal static composition under a full-screen clip and zero draw flags. It does not establish hover/input behavior, callback timing, the network menu branch, live original draw flags, analog VGA fidelity, or runtime parity. No cause of the run002 missing labels is inferred from this comparison; the independently proven English installer alias is the separate run003 observation hypothesis.
