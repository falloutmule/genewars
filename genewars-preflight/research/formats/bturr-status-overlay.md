# BTURR post-image overlay contract

This is a bounded source-derived extension to the selector-1 BTURR main-image renderer. It covers the later image overlay selected by `43A40` and the `982E0` component wrapper into the indexed pixel writer at `A7730`. It does not add or claim a BTURR shadow pass, live draw ordering, or a complete building scene.

`0x11680C` is the rebased animation-table pointer for `PLGBL.ANB`. The source-backed loader row is descriptor `0x103D88`, filename `data/plgbl.anb`, with its file pointer stored at descriptor `+0x1C` (`0x116808`). Startup calls `154B0` over the descriptor table, then `1D770` calls `98A60` and stores its returned animation-table pointer in `0x11680C`. The durable mapping is [building-plgbl-overlay-contract.json](../ghidra/building-plgbl-overlay-contract.json).

The four post-image animation table entries are `+0x14` (animation 2), `+0x6E` (11), `+0x78` (12), and `+0x82` (13). `98A60` returns file `+0x0E`, rebases animation frame pointers, and arithmetic-shifts signed frame dimensions and component offsets by one. The current decoded PLGBL input is 40,414 bytes with SHA-256 `A39CC8AC8C987DE5C4865EC77A4459221F276286F254653E4A3F3231424F6444`; the original 13,697-byte resource SHA-256 is `CCE0F7DE88F2DC8EC251E70925DE93D6E406C109D0BEA9A82F4EE7F1592C9A30`.

For the bounded post-image selection in `43A40`, drawing requires the building owner to equal the explicit selected owner, shade byte `+0x17` to be nonzero, and global frame phase `(frame & 0x3F) >= 0x20`. A set `+0x31` word bit `0x0100` selects animation 11. Otherwise, a clear low bit selects animation 12 only when grade bytes `+0x2E` and `+0x2F` differ. Completed records use the explicit signed threshold value supplied by the caller: if word bit `0x04` is clear, the health/phase branch selects animation 2 or 13; when both base and low-health conditions hold, global phase `(frame & 0x7F) < 0x40` chooses animation 2 and the other half chooses animation 13. Other completed cases may draw no overlay. Threshold table admission is kept separate from this helper.

The overlay origin uses the incoming signed-word X after the wrapper's odd-byte adjustment from record `+0x30`; Y is signed-word `(incoming Y - 10)`. The admitted PLGBL entries have one 23×23 component at local offset `(-11,-11)` after `98A60` relocation. Their source sprites each have 409 literal/opaque pixels, including literal palette-index zero; transparent RLE runs leave destination pixels untouched. The bounded pixel adapter accepts base flags 0 or 4. Flag 4 uses `MAIN.GLA[(source << 8) | destination]`; component flags are zero for these entries.

The source scope for the rendering path is pinned by four instruction listings: `43A40` SHA-256 `62A4377CB232402BE9CF5A1FB0C7DA61D29CC582632C60C217B0357E2961FF1B`, `982E0` `2F34698B16267DA198CE40F56B82157367C539A43A8A15F1C4DAC7001D94C5B3`, `A7730` `AA63D9CAF20FBCD13F8D139958DF0E542A2CA45437A42B7249C87ADBE9A60F00`, and `98A60` `75B266F751D4C7D29DC4D5BF83493B821CDB38F7E10838403DAA29AC1FDC4A8A`. These bounded paths contain no call to `96AC0`; that establishes no shadow call in this overlay path, rather than a general absence of building shadows elsewhere.

The independent source-derived full-frame vectors and input pins are in [bturr-status-overlay-pixels-current.json](../integration/bturr-status-overlay-pixels-current.json), produced by `scripts/desktop/validate_bturr_status_overlay_pixels.py`. A separately written standard-library Rust harness decodes and draws the same selected PLGBL frames; Python and Rust match byte for byte across ten complete 640×480 padded framebuffers. The checks cover owner/shade/phase gates, all four animation selectors, flag-0 and flag-4 pixel paths, clipping, untouched pitch padding, and transactional rejection for invalid flags/table/destination extents. This verifies the bounded source model and resource decoding, not a framebuffer capture from the original executable.

## Bounded API shape

The production adapter should keep three concerns separate:

* `BuildingStatusOverlayDatabase::load_decoded_plgbl(Vec<u8>)` admits only the pinned 40,414-byte decoded hash and the observed 44-animation ANB section layout. It stores the four validated single-frame `IndexedSprite` records and their relocated local offsets; it does not bind an original process pointer.
* `plan_bturr_status_overlay(&[u8; 67], OverlaySelectionContext)` returns either no overlay or a typed animation/origin plan. The context supplies the signed-word incoming point, selected owner, global frame value, admitted base flags, and an optional signed completed-health threshold. A completed record requires that threshold; the helper does not infer a gameplay table or health policy beyond the pinned branches.
* `draw_bturr_status_overlay(database, plan, optional_main_gla, clip, pitch, destination)` accepts only flags 0 or 4, validates the minimum addressed extent and exact 65,536-byte GLA table when needed, draws into a staged destination, and commits only after successful validation. The return receipt should identify the chosen overlay animation, origin, written/clipped pixels, and explicitly state that the separate shadow pass is omitted.

These names describe the adapter boundary, not a source function export. The resource parser and selection plan can be reviewed independently of the later building-scene assembly.
