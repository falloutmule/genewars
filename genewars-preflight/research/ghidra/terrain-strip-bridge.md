# Explicit terrain strip traversal

`0x7B7F0` accepts a context pointer in EAX, strip column in EDX, vertical top in EBX, and vertical bottom in ECX. The safe planner accepts an exact 229,376-byte map region, camera components 0 through 127, column 0 through 19, `0 <= top < bottom <= 480`, and an explicit context-flags byte corresponding to object+`0x1C`. These bounds are port restrictions. No initial camera, viewport rectangle, factor state, or context flags are inferred.

For column c, define `n=c>>1`, `p=c&1`, `x0=cameraX+n`, `y0=cameraY-n-1-p`. The first A baseline is `-16*(1+p)-top`. Pair k samples unwrapped cells A=`(x0+k,y0+k)`, B=`(x0+k,y0+k+1)`, C=`(x0+k+1,y0+k+1)`, D=`(x0+k+1,y0+k+2)`. Lookups wrap each coordinate with `&127`; geometry remains unwrapped. C and D become the next A and B. Screen positions and per-vertex shade follow the established [projection contract](terrain-projection-bridge.md): x=`32*(dx-dy)`, y=`16*(dx+dy)-2*(signed_height>>6)-top`, S=`4*signed_light*factor+32768`.

Each pair first submits A,C,B using A's texture/orientation and UV corners 0,2,3, then B,C,D using B's texture/orientation and corners 0,1,2. Each half is skipped only when all three projected y values are strictly negative; y=0 admits it. The triangle routine performs its own clipping and winding checks. After both halves, continue if `bottom-top>D.y` or `bottom-top>C.y`; otherwise stop. Signed16 heights cap upward displacement at 1022, so the admitted bottom<=480 domain stops within 48 pairs. The planner compares this direct formula with independent cached vertex/baseline evolution.

Before the first half's cull, context flag 4 requests A's byte+11 be ANDed with `0xFB`. Before the second half's cull, it requests B's byte+11 be ANDed with `0xF7`. These occur even for skipped triangles. The safe planner returns these state-change requests, preserving A/B order, without mutating its input region. The cleared bits do not affect the base mode or the later debug-overlay predicates.

For an admitted half, submit the base call first. Its mode is 0 if all three shade values are zero, otherwise 5. The original also compares the newly sampled C/D cell pointer with `0x16E098` for a mode-zero fallback. Exact map cells occupy `0x11C2BE..0x1542BE`, so that pointer equality is unreachable in this admitted map representation. Base texture byte+4 must be 0 through 159 when a call is emitted; skipped halves do not dereference it. Orientation is `(byte+5 & 0x70)>>4`.

Next, owner byte+13 greater than 1 submits mode 6 with the same geometry, UV and shade. Its texture pointer is `0x115E60[index]`, where index is 2 for values>=97 and `(value-1)//32` otherwise. Finally, context flag `0x40`, owner byte+11 bit0 set, and the other cell's byte+11 bit5 clear submits mode 15. For the first half owner is A and other is B; for the second both are B. Mode 6/15 pixel semantics and overlay resources are separate work. Their requests must remain visible; omitting them does not produce a complete original terrain frame.

The outer caller `0x83B20` has a main interval starting at column 0 when object word+`0x1D` is zero and at 4 otherwise. It ends before `trunc(signed_word(+0x33)/32)+start`. An optional right seam extends to column 20; vertical scroll wrap can split the region into separate calls. This receipt establishes one complete strip and records that caller context without inventing initial object values or claiming all dirty-region/scroll callers are implemented.

The validator pins two private instruction listings, checks 960 complete synthetic strips against independent cache evolution, and hashes three full outputs from the exact CD CONQ001 map with explicitly supplied cameras. Those resource-derived outputs remain private. Public vectors use generated cells only. The private fixture cameras are test inputs, not startup-state claims.
