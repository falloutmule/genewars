# Loaded plant state and first scheduled updates

`plant-startup-evidence.json` pins nineteen listings and the exact CONQ001 source. `validate_plant_startup_bridge.py` validates every source plant's cell-list membership, a sequential two-update fixture, all 513 admitted cursor values, 262,136 register-style growth cases and fifteen growth/retirement vectors. This is a bounded state plan, not a complete first mission tick.

The receipt separates `source_fixture.source_sha256` (CD entry152, SHA-256 `72368fc1827142a2fc5da0b30d62c7b9907480f9e6514c1b587cea38159e34d2`) from `source_fixture.fixture_sha256` (the derived private sequential-update JSON). Positive growth preserves runtime byte +0x30; only entering `0x6C780` replaces it with the resource delay. That resource field remains read-only.

Loading gives forty active numeric-family-1 records, indices0–39, animation0/frame0, flags +0x15 equal to 4, flags +0x2E zero and counter +0x2F zero. Initializer `0x6C690` binds each resource and clears the cached frame pointer +0x27. It preserves the serialized animation/frame bytes. Mission entry calls `0x72AD0`, whose final `0x72960` refresh computes shade +0x17 from the final explicit map light/factor data before the module transition. Raw source shade zero is therefore not the live shade.

Module initialization `0x2BBE0` performs its locked terrain draw after `0x82BD0/0x829A0/0x84310` and before the next `0x1C120` entity update. With an explicitly fresh empty queue, this draw has no newly queued plants. The main loop subsequently runs input production, `0x1C120`, then display drawing. A claim about the first live entity frame must include those intervening updates.

In the ordinary family-1 update `0x6D0B0`, the signed16 remaining count controls an ascending slot scan. Inactive slots and flags +0x15 mask0x01 are skipped without consuming the count. Each other active slot consumes one count even if its scheduled callback retires it. At most two slots matching the cursor call virtual +0x64. The cursor initially advances by eight; a signed result greater than 512 becomes `(result+1)&7`. It advances again after each scheduled call. Source count40 and cursor0 give scheduled indices8 and16, then cursor24. Flag +0x2E mask0x10 suppresses later queue admission, but does not itself suppress the scheduled call. Safe scheduling must validate enough eligible slots; the original has no array-end guard. The creation-count second pass remains outside a plan that admits only zero-created callbacks.

The first-counter lifecycle slice requires growth>0, counter +0x2F zero, flags +0x15 mask0x01 clear, flags +0x2E mask0x9A clear, cell +13 positive, resource check threshold +0x1B positive, and spread period +0x18 greater than one. It increments the counter to one. The nine-cell positive-growth count accumulates with byte wrap. If that byte exceeds resource crowd threshold +0x1A, growth becomes zero. Otherwise add the signed resource byte at +0x10+terrainClass to the signed16 growth word, preserving word wrap, then cap only the upper bound at 32. Positive growth selects `max(oldAnimation,min(growth>>3,2))`; a changed animation sets flags mask0x04. Counter1 modulo period is nonzero, so this admitted slice cannot spawn or call its random path. Frame byte is preserved.

Zero or negative growth enters `0x6C780`: animation adds six with byte wrap, growth becomes zero, flags +0x2E gains mask0x80 and counter +0x30 receives resource retirement delay +0x1D. A delay at least four is reduced by four and the record stays active. A delay below four immediately requests cell-list unlinking, increases cell +13 by two only when its old value is below64, clears the active type byte and decrements the plant count. Owner0–3 additionally requests a word decrement at player+0x5FA; owner4 skips it; larger owners are safely rejected. The original can turn cell value63 into65. The old-frame dirty check must retain its current-view gate and null cached-frame behavior. That check and reference/UI/audio cleanup remain explicit requests, not hidden mutations.

The source-linked sequential fixture has record8 with seven positive-growth neighbors versus threshold2; after its removal record16 still has five versus threshold3. Both delays are three and owners are four. Thus both immediately retire, plant count40 becomes38 and both active bytes clear before queue admission. Their transient animation6 is not a rendered death frame. The validator rewrites predecessor/next cell references and proves the remaining 38 plants are linked exactly once.

`0x724C0` clears matching target-reference type bytes in other active families, may restore the default panel if the removed entity was selected, and calls two bounded cleanup helpers. `0x409F0` clears matching pointers in nine attachment slots; `0x2C200` clears matching pointers in two active panel variants. These helpers do not change plant growth or the map's light/height/factor inputs. A pure plan should retain their requests and leave UI/audio/world cleanup to the caller.

Capacity is also a runtime boundary. The loaded source has one active family0 record and forty plants, but player-entity creation and preceding family updates can change the live population. An explicit prior accepted queue count at most216 leaves room for all forty plants; larger counts must use the established 256-entry admission contract. This tranche does not execute or approximate preceding family0 AI, actor creation, visibility callbacks, or a whole live tick. Its fixture explicitly starts from the validated loaded state, and its shade contract takes the final map snapshot as input.
