# Mickey-driven software cursor and Options keyboard path

`mouse-motion-evidence.json` pins fifteen private listings. `validate_mouse_motion_bridge.py` checks 516,096 signed-counter/sensitivity/remainder cases and six movement vectors without executing original code.

The game registers INT33 function0C with mask0x7F and callback `0xA3524`. Its callback prologue helper changes DS only. The movement branch consumes **SI/DI mickey-counter words**, subtracting each previous sign-extended word from the new sign-extended word. It does not move the game cursor from callback absolute CX/DX. The [FreeDOS mouse interface documentation](https://raw.githubusercontent.com/FDOS/mouse/master/int33.lst) corroborates the distinction between cursor position and mickey-count registers. No driver code was copied.

The accumulator divides `(new_counter-old_counter+remainder)` by sensitivity1–63 with floor division and a nonnegative remainder. The signed16 counters are widened before subtraction; there is no word-wrap correction. Software initialization sets the game's own cursor to (320,240) for 640x480. Its own clamp gives x0–639/y0–479, and the packet producer copies those software coordinates. Button latches also use the software position.

Counter processing requires the active-mouse global and movement event mask0x01. Immediate coordinate addition also requires both inhibition globals `0x19F350` and `0x19D220` zero. The callback updates saved counters and pending deltas before those immediate gates; helper `0xA2ED4` can apply pending deltas later. An immediate inhibition branch alone therefore does not prove a permanent freeze.

This gives a specific conditional explanation for working clicks at a stationary center: host absolute events may change CX/DX and button events while SI/DI remains unchanged. Static code cannot establish that the emulator actually delivered such registers. The next discriminating probe is an independent empty DOS program logging callback AX/BX/CX/DX/SI/DI into memory, comparing absolute host injection with relative/captured motion, and writing its log only after unregistering. Polling INT33 function0B during capture could change the counter experiment and should be avoided.

Options module `0x18653C` resolves its input callback through `0x13B10` to `0x24200`. It uses the mouse manager and restores the previous module through control ID9 at `0x245B6`. With no active text-edit field, neither this handler nor the manager implements a standalone Escape exit. The global keyboard dispatcher tests event values0x10/0x19/0x23/0x4A; raw event0x01 falls through and is cleared. Its IRQ source reads port0x60 directly. Escape failing to close Options therefore does not by itself establish broken keyboard delivery. Active text editing and modal keyboard paths remain separate.
