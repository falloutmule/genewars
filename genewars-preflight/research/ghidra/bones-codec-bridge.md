# BONES caller and codec admission

The exact CD/root-1 BONES input SHA-256 `2106ce79deaafe53d5fbb6292c78a8c71fb6920b08d1a11b5c44ea3b0ab75e9f` is admitted separately as packed4. Its earlier indexed8 stream-truncation finding was a rejected codec model, not proof of corrupt or unused data. It is outside the 25-name creature-table receipt because its loader is a separate descriptor.

The static pointer chain in the provisional CD GW.EXE candidate is concrete: descriptor `0x10401C` names `data/creature/bones.anb`, destination `0x116800`; startup `0x1D9C4/0x1D9C9` passes that allocation through loader `0x98A60`, storing the resulting animation base at `0x116804`. Selector `0x5A1C0` tests unsigned entity byte `+0x5E >= 0x1A` and, on that branch, writes this BONES animation base to entity `+0x1F`. No gameplay label is assigned to the byte.

Entity draw instruction regions read the same `+0x1F`, select a ten-byte animation and fourteen-byte frame, and call `0x94910` (calls at `0x59A6C/0x59AB6`) or `0x94D70` (`0x59B59`). These frame walkers obtain sprite descriptors through components and call `0x90460` or `0x94400`. Their positive-run advancement explicitly uses `floor(N/2)+(N&1)` bytes. Their pixel loops read high nibble then low nibble; the scaled path dispatches to the same consumer at scale >=256. These are packed4 consumers with additional lighting/translation behavior. That extra color behavior is outside the raw-index decoder contract.

The existing explicit packed4 decoder is sufficient for raw nibble indices and opacity. All ten nonempty records are bounded by the sprite-data boundary 3721; the last stream ends exactly there. Many rows have fewer controls' worth of pixels than the declared width. The unmentioned remainder is transparent; requiring every row's run sum to equal declared width would incorrectly reject these sprites. There are no row overshoots. Record zero has zero dimensions and is inactive. The receipt includes full index and opacity hashes for each active record, plus consumed ranges, for independent comparison without publishing extracted pixels.

`python -B scripts/ghidra/validate_bones_bridge.py` checks the source hash, two source aliases, loader/selector/frame/blitter instruction contracts and bounded streams, then writes `bones-evidence.json`. Admission applies only to that exact source hash; optional palette translation, lighting, scaling and flip are excluded. GPF remains unresolved and blocked. No original executable was run by this tranche.
