# Mode-five triangle row preparation

The exact candidate's `0xE1900` dispatches mode five through four preparation paths: right-middle `0xE1AD3`, left-middle `0xE23E0`, flat bottom `0xE2D0E`, and flat top `0xE318D`. Their output feeds the separately verified [horizontal sampler](mode5-span-bridge.md). This contract chooses no camera, initial shade, visibility, texture, or draw order. The receipt pins private listings and gives eight complete synthetic row vectors; the validator compares closed-form rows with repeated register-style additions across 2,528 cyclic, clipped, and winding cases.

Each input vertex is five signed 32-bit values: integer `x,y` and 16.16 bitpatterns `U,V,S`. Preserve cyclic vertex order. Rotate the order to identify the top; do not freely sort vertices and discard winding. For a flat top, the cyclic order is left top, right top, bottom. For a flat bottom it is top, right bottom, left bottom. A reversed flat edge returns without drawing. For distinct y values, the two cyclic possibilities are top, right middle, bottom and top, bottom, left middle. The source's slope comparisons further reject reversed or sufficiently narrow triangles.

All additions and subtractions wrap at 32 bits. Signed division truncates toward zero; arithmetic shifts round downward. Define `edge(a,b,H)=trunc(wrap32((b.x-a.x)<<16)/H)`. Coordinates admitted by the safe port are -4096 through 4096, and clip height is 1 through 480. Attributes may use every signed32 bitpattern. These are explicit implementation restrictions, not validations claimed for the original.

Rows cover `max(top.y,0) <= y < min(bottom.y,clip_height)`. `0xE88A3` stores the supplied buffer at `0x100104` and buffer-minus-pitch at `0x100100`; the sampler's pre-increment therefore draws each row at the expected y. Each prepared row contains left x, right x, U, V, S; x edges are 16.16. Attributes are anchored to the left edge without compensation for its fractional x. Horizontal sampling floors both x edges, uses right-exclusive coverage, and handles negative x in the separate span contract.

For flat top `L,R,B`, height is `H=B.y-L.y`. Left/right x begin at `L.x<<16` and `R.x<<16` and advance by `edge(L,B,H)` and `edge(R,B,H)`. For each attribute A, horizontal gradient is `trunc(wrap32(R.A-L.A)/(R.x-L.x))`; the initial value is `L.A`, and its row gradient is `trunc(wrap32(B.A-L.A)/H)`.

For flat bottom `T,L,R`, height is `H=L.y-T.y`. Both x edges begin at `T.x<<16`, then advance by `edge(T,L,H)` and `edge(T,R,H)`. Attribute horizontal gradient is `trunc(wrap32(R.A-L.A)/(R.x-L.x))`; initial value is `T.A`, and row gradient is `trunc(wrap32(L.A-T.A)/H)`.

For a general triangle use top T, middle M and bottom B, `H=B.y-T.y`, `h=M.y-T.y`, and `r=trunc((h<<16)/H)`. The long slope is `edge(T,B,H)`, upper short slope `edge(T,M,h)`, and lower short slope `edge(M,B,H-h)`. A right-middle triangle requires upper short slope strictly greater than long slope. A left-middle triangle requires long slope strictly greater than upper short slope.

The general gradient width is deliberately rounded before division. Let `low_product_shift(a,r)=wrap32(a*r)>>16`, using the low32 product and arithmetic shift. Right-middle width is `wrap32(M.x-T.x + low_product_shift(T.x-B.x,r))`; left-middle width is `wrap32(T.x-M.x + low_product_shift(B.x-T.x,r))`. Negative width returns without drawing. Width zero skips initialization of gradient stack fields in the original, so the safe API rejects it. A positive width uses denominator `width+1`.

For attributes, `product_shift(a,r)=wrap32((signed64(a)*r)>>16)` uses the signed64 product, matching `IMUL` followed by `SHRD`, rather than the low32 x-width operation. Right-middle horizontal gradient is `trunc(wrap32(product_shift(wrap32(T.A-B.A),r)+M.A-T.A)/(width+1))`. Left-middle horizontal gradient is `trunc(wrap32(product_shift(wrap32(B.A-T.A),r)+T.A-M.A)/(width+1))`. Standard determinant or barycentric division would change this rounding and denominator.

Right-middle attributes start at T and advance toward B by `trunc(wrap32(B.A-T.A)/H)` throughout. Left-middle attributes advance toward M by `trunc(wrap32(M.A-T.A)/h)` above the middle, then use `trunc(wrap32(B.A-M.A)/(H-h))` below it. At the middle, reset the short x edge exactly to `M.x<<16`; keep accumulated attributes. In particular, left-middle does **not** reset attributes to M, preserving division remainder lost above it. Vertical clipping advances these same accumulators through omitted rows with wrapped multiplication/addition.

The public validator is an original mathematical specification and never executes original instructions. Private disassembly and mapped bytes remain excluded from source artifacts. Full texture/shade address bounds and positive clip-width admission belong to the sampler contract; zero index still produces an opaque write.
