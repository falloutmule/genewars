# Verified static renderer and sprite bridge

Scope: the provisional CD executable SHA-256 `4bdf296febc88984aab6939fe3f3ef3196891f0be9bcb84a9283ab3b668a60ba`, loaded with independently verified LE mapping. This is not a canonical retail baseline. No original code was run. Addresses below are loaded virtual addresses in object 1 unless identified as data. Raw listings, decompilation, and mapped bytes remain private. `renderer-evidence.json` records hashes and repeatable receipt checks.

## Panel pixels and display pitch

The three-pointer table at data VA `0x105604` selects `data/mainpanl.dat`, `data/genepanl.dat`, or `data/lpanel.dat`. Loaders `0x24770` and `0x24A60` allocate `0xF000` bytes and load the selected file through `0x154F0`. These are panel backgrounds; the separately named `.ANB` resources are not interchangeable with them.

Draw routine `0x24AD0` takes a structure pointer in EAX, dereferences twice for its source buffer, and takes destination in EDX. Each row copies 32 DWORDs, advances source by 128 bytes, and advances destination by `(global_pitch >> 2) * 4`. It repeats `global_height` times, or does nothing for signed height <= 0. This proves 128-byte source rows, a destination step rounded down to a multiple of four, and no panel-local height header. The caller must provide sufficient source and destination storage.

Display initialization `0x1CAA0` passes width 640, height 480, mode index 13 and palette pointer through `0x979A0` to `0xA13F0`. The latter assigns those dimensions to pitch/height globals `0x19CF6C`/`0x19CF70`. Caller `0x82BD0` reserves a 128-pixel panel width and adjusts the main render region accordingly. The alternative setup path also explicitly assigns the 640/480 globals; this dossier does not establish every video mode's framebuffer behavior.

Consequently the decoded GENEPANL background is an indexed 128-by-480 raster with source stride 128 in this path. This conclusion uses instructions and caller setup, not just factorization of its 61,440-byte length. Decoded SHA-256: `af9741b4545fb6f28a1dd0e50da0570e39992e75c872bc2249891f3330f59951`.

## Exact palette association

Startup `0x1D770` calls descriptor loader `0x154B0` on the list at data VA `0x104360`, then display initialization `0x1CAA0`. Descriptor `0x1043E4`, the fourth 44-byte entry, names `data/main.pal`; its allocation-destination field at `+0x1C` points to global `0x115E80`. Through `0x15410`, actual descriptor loader `0x9A09C` loads the filename and assigns the allocation through that field. Display setup reads that same global, passes it through `0x979A0` and `0xA13F0`, and invokes palette uploader `0xA6D2C` when nonnull. This connects MAIN.PAL to the panel display path without substituting a menu palette.

MAIN.PAL is a raw 768-byte CD member `GAME/DATA/MAIN.PAL;1`, inventory entry `root/2/disc/108`, LBA 7491. Full ancestry is `genewars.zip!/Genewars_DOS_EN_ISO-Version.7z!/Gene_Wars_ISO/GENEWARS.img!/GAME/DATA/MAIN.PAL;1`. SHA-256 is `8d9a27bca8ed203629da4ee72bb982150fae5dd876743b50a99ad90dba0f4b05`. Both inventoried RIP copies have the same hash. The local validator independently reads the CD sector and verifies this hash and values <= 63.

Uploader `0xA6D2C` writes mask 255 to port `0x3C6`, selects each index 0..255 through `0x3C8`, then writes three successive input bytes unchanged to `0x3C9`. Reader `0xA6CE0` reads corresponding triplets. VGA DAC semantics establish RGB order and six-bit channels; see the [FreeVGA DAC register reference](https://www.scs.stanford.edu/10wi-cs140/pintos/specs/freevga/vga/colorreg.htm). There is no six-to-eight-bit scaling in this uploader. A modern RGB8 renderer must declare its conversion rule; that rule is a new display mapping, not an observed original arithmetic operation. Keep palette indices intact when exporting indexed images.

## Sprite records and ANB sections

Table fixer `0xA7618` takes EAX=start, EDX=end, EBX=sprite-data base. It advances by six bytes; for each record it reads a u32 at +0 and, when that value is below the base, adds the base and writes the resulting pointer back. Already based values are left unchanged. Draw routine `0xA7730` reads u8 width at +4, u8 height at +5 and pixel pointer at +0. Either zero dimension returns without drawing. Thus an on-disk six-byte descriptor can be represented independently as `{relative_data_offset:u32_le, width:u8, height:u8}` without copying the loader's in-place mutation.

ANB loader `0x98A60` reads a u16 at +0 and four u32 section offsets at +2, +6, +0xA, +0xE, then rebases each to the file start. Its six-byte sprite table runs from section +2 to section +6. It calls `0xA7618` with sprite-data base **file start + 0x12 (18 decimal)**. The following sections use ten-byte records [+6,+0xA), fourteen-byte records [+0xA,+0xE), and a final count * 10 bytes starting at section +0xE, where count is the header u16. Pointer fields in these later sections are rebased to the preceding section; signed coordinate fields are shifted right one, and flag bits may be adjusted. Those later animation semantics are not yet a portable animation API.

Startup separately demonstrates a raw DAT/TAB pair: descriptors `data/pointers.dat` at `0x103DB4` and `data/pointers.tab` at `0x103DE0` assign globals `0x11698C` and `0x115E74`/`0x115E78`. Instructions `0x1D9CE–0x1D9E4` pass the DAT base and TAB bounds to `0xA7618`. This pair uses the DAT allocation as base; it does not justify blindly adding 18 to every DAT/TAB resource.

The basic, unblended scanline path in `0xA7730` starts at `0xA7E77`: positive signed control 1..127 copies that many literal palette indices, negative -1..-128 advances the destination transparently by its magnitude with no literal payload, and zero ends the row. Data is sequential with no per-row offset table. Positive controls always advance source by full run+control even when clipped; after visible width is exhausted the code scans to the next zero terminator. An early zero also advances the row, so exact equality of run totals and declared width is not a proven validity requirement. A safe decoder can leave an early-ended row remainder transparent and clamp visible runs while consuming their full payload. It must bounds-check every source access and consume exactly height row terminators for a complete standalone decode. Trailing ANB data may be other sprites or sections.

Flip bits 1/2, clipping and blending bits 4/8 have additional paths in this routine. A first independent renderer may implement only the basic unblended image decode and expose transparency explicitly. It must not claim original clipping, blend tables, frame sequencing, or timing until separately verified.

Luna's format receipts track exact decoded ANB/TAB pair tests. IFEDITOR's external 264-byte TAB equals its ANB embedded first section at offset 29,875, and the root/4 IFCUSTOM 78-byte TAB (the package with the larger 5,184,949-byte GW.EXE and the 11,338-byte IFCUSTOM resource) equals its embedded first section at offset 10,912. This independently corroborates those exact pairs. LEVEL's external 216-byte TAB differs from its embedded 240-byte section; the larger IFCUSTOM's embedded section is 222 bytes and differs from the external 78-byte TAB. Their bounded RLE decoding success does not establish intended pairing. Preserve archive provenance. The earlier IFCUSTOM filebase bound warning is superseded by use of the proven ANB sprite-data base +18; it is not evidence of corrupt input.

## Review locations and limits

Private evidence folders: `panel-verified` (recovered loader and panel draw), `mode-functions` (display dimensions/wrapper/caller), `descriptor-loader` (actual file loader), `vga` (DAC upload/read), `sprite-functions` (table, ANB sections, pixel draw), and `sprite-references` (direct callers). Function `0x24A60` was recovered from its prologue and verified pointer context; the earlier speculative `0x24A80` mid-instruction output is rejected and must not be used. `0xA7618` returns through shared epilogue `0xA75D9`, outside its exported contiguous instruction range.

Run `python -B scripts/ghidra/validate_renderer_bridge.py` from the project directory. It checks candidate/asset hashes, pointer-table/descriptor associations, eight instruction-listing contracts and four synthetic destination pitches. These are static receipts and abstract row-copy checks, not original runtime comparison. Mapped hashes in the JSON cover the contiguous start-plus-address-count span and are labeled accordingly; listing hashes identify the exact exported artifact. Unknown compiler convention and speculative automatic function naming remain as in `function-tranche.md`.

The later creature-codec-bridge.md supersedes any corpus-wide indexed8 grammar assumption: the 25 admitted creature resources use caller-selected packed4 literal pixels. UI consumers and the exact CD IFCUSTOM binding retain the indexed8 contract. Codec selection requires caller evidence and exact input provenance.
