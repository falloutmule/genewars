# Typed plant state and subsequent callback steps

The parameter table is initialized data in the pinned candidate executable, not sprite data. `plant-state-evidence.json` binds twelve32-byte records at mappedVA `0x104B80` to exact file bytes `[0x126980,0x126B00)`, SHA-256 `297a1da0e9c30d6d4cb7c88addb8234be260e0e93b7d4b2b1c4c3ad8b7df2b7c`. The extraction validator creates a standalone private384-byte file so runtime code can read the verified table without executable input. Preserve unnamed bytes opaque. Interpreted fields are eight signed growth deltas at+0x10, period+0x18, random-walk steps+0x19, crowd limit+0x1A, check threshold+0x1B and retirement delay+0x1D.

The source/native field mapping, three-byte references, map heads and owner/count offsets are recorded in that receipt. Its private fixture contains all40 loaded plants, twelve interpreted parameter records and41 nonempty cell heads. Raw owner counts0..3 are zero; these are source facts, not substitutes for retained or updated live player state. Runtime pointers and final shade are separate.

`plant-step-evidence.json` and its validator extend the closed first-counter slice to subsequent no-RNG callbacks. Positive starting growth increments the byte counter first, then compares the **old** unsigned counter with the check threshold. If the old counter has reached the threshold, or cell+13 is zero, subtract four from the signed growth word and skip neighbor queries, division and RNG. Otherwise crowding can set growth zero directly. The delta branch adds its signed byte with word wrap and caps only the upper bound at32, then checks the **new** counter modulo the period.

A period boundary with live plant count below412 for owner4 or512 for owners0..3 requires reproduction. This plan reports an unsupported branch instead of silently skipping its RNG/creation. At/above that count boundary the original skips reproduction, so the parent-field step remains closed. Period zero is a source division fault on the delta branch and is safely rejected. Reproduction is checked before final retirement, even if the updated growth became nonpositive.

Starting nonpositive growth preserves the update counter and goes directly to retirement. `0x6C780` adds animation6, zeroes growth and loads the resource delay only when flags+0x2E mask0x88 is clear. Later calls with either mask bit set retain those fields and decrement the current runtime delay by four while it is at least four. A smaller delay requests cleanup and clears active type. Thus fresh delay `d` retires after `floor(d/4)+1` calls. An existing retirement flag can preserve a negative growth word; do not force it to zero on every call.

The final dirty mask0x04 is set when animation changed or flags+0x2E mask0x02 is present. Early suppression by flags+0x15 mask1 or flags+0x2E mask0x10 skips that final logic entirely. Cleanup remains explicit, following the preceding retirement receipt. These rules support stateful plans on caller-supplied live state and do not claim a full world tick or completed reproduction model.
