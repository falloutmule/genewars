# Terrain draw modes 0, 6 and 15

The dispatch tables bind mode 6 to exactly the same four triangle preparation targets as mode 5. Modes 0 and 15 share four geometry-only preparation targets. Their pixel routines are respectively `0xE357F`, `0xE42AA`, and `0xE5B70`. The receipt pins nine private instruction exports. No original instructions are executed by the validator.

Mode 6 accepts the [prepared rows and gradients](mode5-triangle-bridge.md), but its sample arithmetic differs from [mode 5](mode5-span-bridge.md). Start from U,V,S, retaining each low24 bitpattern as 16 fraction bits and eight integer bits. For every sample, use `u=(U>>16)&255`, `v=(V>>16)&255`, and `shade=(S>>16)&255`, then independently add dU,dV,dS modulo `2^24`. All 16 shade fraction bits are retained. The literal `ADD DX`/`ADC BL`, `ADD EDX`/`ADC BH`, `ADD ECX`/`ADC AH` chain matches these independent accumulators; it does not have mode 5's coupled carry behavior.

Horizontal coverage uses floor integer edges and the same left-inclusive/right-exclusive interval. The safe mode 6 API requires clip width 1 through 640, ordered integer edges between -4096 and 4096, and checked source addresses. If left is negative, advance full32 U,V,S by `(-floor(left))*gradient` with wrapped arithmetic before taking their low24 bits. Empty spans sample nothing. These restrictions exclude unsafe zero-width and inverted-edge paths of the original word-based loops.

Read source at `texture_base+v*256+u`. Source index zero skips both the FADE read and the destination write; every accumulator still advances. For nonzero source, output `FADE[shade*256+source]`. Exact FADE length is 16,384 and an accessed shade byte must be below 64. A zero source with shade byte 255 is valid because FADE is never accessed. Return pixels together with a write mask, preserving the prior destination for mask-zero samples. A nonzero source that maps through FADE to zero still writes an opaque zero.

The overlay pointer producer is the existing B32A table loop in `0x1D770`. `0x115E60 == 0x115BEC + 157*4`, so overlay indices 0,1,2 resolve to tiles 157,158,159 of the same 163,840-byte atlas, with base offset `(tile//8)*8192+(tile%8)*32`. There is no separate overlay resource. The mode 6 receipt hashes complete 32×32 shaded pixels and write masks for all three actual tiles at explicitly selected shade row 32; those outputs remain private. The row is a test input, not an initial-state claim.

Modes 0 and 15 prepare only x edges using the same cyclic ordering, slope culling, exact middle-edge reset, and vertical coverage as the textured triangle path. They do not compute attribute gradients or the general triangle's rounded width. Consequently, the narrow general-width-zero case that safely rejects in mode 5/6 remains admitted for mode 0/15. The receipt includes its exact three geometry rows.

Mode 0 fills covered pixels with an explicit unsigned color byte. Mode 15 reads each existing destination index d and writes `MAIN.GLA[d*256+color]`; the destination is the high-byte index and color the low byte. Both use color zero in `0x7B7F0`, which initializes global `0x102E24` to zero. The mode 15 table is exactly 65,536 bytes. Startup `0x1DC79..0x1DC88` loads `data/main.gla` to `0x18CF48`. Exact CD member 107 has compressed SHA-256 `c5e12a5b4325c8302cab0fb3ba3aaa654e2e044131763298815766d8a6f47a58`; its decoded SHA-256 is `bf841a1c4fca2a80fbef3c2fd6b502c4af34ede8e67b41ff69f64836726ea5b3`. This proves lookup orientation and binding, without naming the table's visual effect or regeneration algorithm.

The public validator exposes `mode6(source, base, fade, width, left, right, attrs, steps)` returning `start`, `pixels`, and `mask`; attributes and steps are U,V,S and dU,dV,dS. `geometry(vertices, clip_height)` returns geometry-only `[y,left,right]` rows for modes 0/15. It checks 1,088 independent carry-chain cases, four complete generated spans, three actual atlas tiles and three full MAIN.GLA destination columns. Camera, factor state, context flags, viewport placement and strip call order remain caller inputs governed by the separate strip receipt.
