# Initial scene viewport and panel placement

For the established 640×480 logical display, startup calls `0x82BD0` with context `0x16E0A8`. It stores word+`0x1D=128`, horizontal buffer offset word+8=128, vertical offset word+10=0, width word+`0x33=512`, and height word+`0x35=480`. Camera reset `0x82E20` retains the panel margin and rewrites those offsets and dimensions. This establishes a left panel rectangle `(0,0,128,480)` and a right terrain rectangle `(128,0,512,480)`.

Camera reset fills twenty dirty-column bytes at context+`0x11BD` with value 2. Draw coordinator `0x86C20` begins at column 4 when the panel margin is nonzero and iterates while column<20. For each dirty byte it calls `0x86840` with column and that byte. Dirty value 2 selects `0x7B7F0`; value 1 has a separate enhanced path that is outside this initial receipt.

With the initialized offsets, `0x86840` supplies the terrain backing buffer `0x115E84` without a base offset and sets clipping to 640×480. It passes zero for the pitch argument, preserving the sampler's previous pitch. This receipt requires that inherited pitch already be 640: startup `0x1D770` assigns it from display width at `0x1DB51` only on its successful display-lock path (`EDX=1`). An unconditional initialization of sampler pitch is not claimed. The strip caller temporarily ORs context flag 4, then calls each strip with top 0 and bottom 480, and clears flag 4 afterward. Thus the complete initial base traversal is columns 4 through 19, each spanning x=`32*column` through `32*(column+1)`. It covers the right 512-pixel region while retaining a full-screen clipping buffer. Existing context flags other than bit 4 remain caller state; no debug or timing flags are invented.

Flag 4 requests the map-byte+11 AND operations recorded by the strip planner. It does not change mode 5/6 pixels. A full-state port must preserve those requests even when a static preview can produce the same pixels with an explicit zero flag. Scroll wrap, incremental redraw, foreground entities and UI timing remain separate contracts.

Panel routine `0x24AD0` copies 128 source indices per row to its supplied destination, using source pitch 128 and display pitch rounded down to a multiple of four, which is 640 here. Calls that supply the backing-buffer base place those pixels at x 0 through 127. The established MAIN.PAL binding supplies the display palette. Panel and terrain rectangles partition all 307,200 display positions without overlap.

Background identity is separate from placement. `0x24770` selects a filename through table `0x105604` using signed byte panel-object+4: selector 0 is `data/mainpanl.dat`, 1 is `data/genepanl.dat`, and 2 is `data/lpanel.dat`. The first mission's active panel selector is not yet established in this receipt. Composing the verified GENEPANL raster is an explicit diagnostic resource choice and must not be described as the confirmed initial mission panel.

The camera used by a source-derived first-mission diagnostic may be `(66,48)` only under the successful CONQ001 load, campaign flag, and selected-player-0 gates in [mission-load-bridge.md](mission-load-bridge.md). This receipt does not add a universal startup-camera claim or complete the original visibility callbacks. The validator pins eight private instruction listings, checks sixteen initial strip argument vectors and all rectangle positions, and records the unresolved background selector explicitly.
